# Transformer — 从注意力到序列转换

:::tip 本章要点
- 理解 **Scaled Dot-Product Attention** 的数学公式和 $1/\sqrt{d_k}$ 缩放因子的作用
- 掌握 **Multi-Head Attention**：多头拆分、并行计算、拼接投影
- 理解三种 **Mask**（padding / causal / source-target）的用途和代码实现
- 读懂位置编码的 sin/cos 公式和训练/推理的输入输出契约
:::

## 1. 从 Attention 到 Self-Attention

[上一章的 Attention](./attention) 是 Decoder 对 Encoder 输出的跨序列关注。Transformer 将这一思想推广为三种 Attention：

| 类型 | Query 来源 | Key/Value 来源 | 作用 |
|------|-----------|---------------|------|
| Encoder Self-Attention | Encoder | Encoder | 输入序列内部的词间关系 |
| Decoder Self-Attention | Decoder | Decoder | 已生成序列的内部关系（causal） |
| Cross-Attention | Decoder | Encoder | Decoder 关注 Encoder 输出 |

三种 Attention 的核心计算完全相同，区别仅在于 Q、K、V 的来源和 Mask 策略。

---

## 2. Scaled Dot-Product Attention

单个注意力头的计算：

$$
\mathrm{Attention}(Q, K, V) = \mathrm{softmax}\left(\frac{QK^T}{\sqrt{d_k}} + M\right)V
$$

其中：
- $Q \in \mathbb{R}^{n \times d_k}$：Query 矩阵
- $K \in \mathbb{R}^{m \times d_k}$：Key 矩阵
- $V \in \mathbb{R}^{m \times d_v}$：Value 矩阵
- $\sqrt{d_k}$：缩放因子，防止点积过大导致 softmax 梯度饱和
- $M$：Mask 矩阵（$-\infty$ 在禁止关注的位置，0 在其他位置）

代码实现中 `MY_INF = 1e12` 作为 $-\infty$ 的近似：

```python
scores = torch.matmul(Q, K.transpose(-2, -1)) / math.sqrt(d_k)
scores = scores.masked_fill(mask == 0, -MY_INF)
attn = F.softmax(scores, dim=-1)
output = torch.matmul(attn, V)
```

### Multi-Head Attention

将 $d_{\text{model}}$ 维的 Q、K、V 拆成 $h$ 个头，每个头独立计算 Attention，最后拼接：

$$
\mathrm{MultiHead}(Q, K, V) = \mathrm{Concat}(\text{head}_1, ..., \text{head}_h) W^O
$$

$$
\text{head}_i = \mathrm{Attention}(Q W_i^Q, K W_i^K, V W_i^V)
$$

每个头的维度 $d_k = d_v = d_{\text{model}} / h$。本项目默认 $d_{\text{model}} = 512$，$h = 8$，$d_k = 64$。

## 3. 位置编码

Transformer 没有循环结构，需要显式注入位置信息。使用正弦/余弦位置编码：

$$
PE_{(pos, 2i)} = \sin\left(\frac{pos}{10000^{2i / d_{\text{model}}}}\right)
$$

$$
PE_{(pos, 2i+1)} = \cos\left(\frac{pos}{10000^{2i / d_{\text{model}}}}\right)
$$

其中 $pos$ 是位置，$i$ 是维度索引。位置编码与词嵌入相加后送入 Encoder/Decoder。

这种编码的一个重要性质是 $PE_{pos+k}$ 可以表示为 $PE_{pos}$ 的线性函数，使模型更容易学习相对位置关系。

### 从 Sinusoidal 到 RoPE

正弦位置编码是 2017 年原始 Transformer 的做法。后续研究发现，把位置信息**直接注入注意力计算**比加在输入上更有效。**旋转位置编码（RoPE）** 是当前的主流方案（LLaMA、FLUX、Qwen 等均采用），其核心思想是：

给注意力中的 $Q$ 和 $K$ 向量分别乘上一个与位置相关的旋转矩阵，使得 $Q_m$ 和 $K_n$ 的内积天然包含相对位置 $(m-n)$ 的信息：

$$
\langle \mathbf{q}_m e^{im\theta}, \mathbf{k}_n e^{in\theta} \rangle \propto f(m-n)
$$

RoPE 带来的一个重要能力是**长度外推**：在短序列上训练的模型，可以通过调整旋转频率（如 NTK-aware scaling、YaRN 等技术）直接在长序列上推理。这对图像生成尤其有意义——在 $256\times256$ 图像上训练的 DiT，可以通过长度外推生成 $512\times512$ 乃至更高分辨率的图像。

> 📖 苏剑林（2021）。[Transformer 升级之路：旋转位置编码](https://kexue.fm/archives/8265)。周弈帆（2024-12-08）。[位置编码长度外推技术](https://zhouyifan.net/2024/12/08/20241208-Context-Window-Extension/)。（本章教程仍使用正弦位置编码以便教学，生产环境建议使用 RoPE。）

## 4. Mask 策略

### Padding Mask（Encoder + Cross-Attention）

英文源序列中的 `<PAD>` token 不应参与 Attention。将对应位置的 score 设为 $-\infty$：

```python
# mask shape: [batch, 1, 1, src_len]
encoder_output = encoder(x, src_padding_mask)
```

### Causal Mask（Decoder Self-Attention）

禁止 Decoder 在生成第 $t$ 个 token 时"偷看"未来的 token $t+1, t+2, ...$。使用**下三角矩阵**：

```python
causal_mask = torch.tril(torch.ones(seq_len, seq_len))  # 下三角为 1
```

### Source-Target Mask（Cross-Attention）

Decoder 的 Cross-Attention 应忽略英文 padding token。直接复用 Encoder 的 padding mask。

## 5. 训练契约

数据加载函数 `load_train_data()` 返回 `(english_source, chinese_target)`。

训练时输入和标签**错开一个位置**：Decoder 输入为去掉最后一个 token 的目标序列，标签为去掉第一个 token 的目标序列：

```python
# y_batch 包含 <S> token, target, ..., <EOS>
y_input = y_batch[:, :-1]   # <S>, target, ...
y_label = y_batch[:, 1:]    # target, ..., <EOS>
logits = model(x_batch, y_input)
```

英文源序列添加 `<S>` 和 `</S>` 边界标记，词表外单词映射为 `<UNK>`。

---

## 6. 自回归推理

解码从中文词表的 `<S>` 开始，每步将当前完整序列送入 Decoder，取最后位置的预测作为下一个 token。生成 `</S>` 后停止：

```python
y[:, 0] = start_id
finished = torch.zeros(x.shape[0], dtype=torch.bool, device=x.device)
for i in range(1, max_len):
    logits = model(x, y[:, :i])
    next_token = torch.argmax(logits[:, -1], dim=-1)
    next_token = torch.where(finished, pad_id, next_token)
    y[:, i] = next_token
    finished |= next_token == end_id
    if torch.all(finished):
        break
```

本实现使用贪心解码（每次取概率最大的 token），未包含 beam search 或 KV cache。
